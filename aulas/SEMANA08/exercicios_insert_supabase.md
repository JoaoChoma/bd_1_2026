# Exercícios — `INSERT` no PostgreSQL/Supabase

Considere as tabelas já criadas:

```sql
CREATE TABLE categoria (
    id_categoria BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    nome VARCHAR(100) NOT NULL UNIQUE
);

CREATE TABLE produto (
    id_produto BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    nome VARCHAR(100) NOT NULL,
    preco NUMERIC(10,2) NOT NULL CHECK (preco >= 0),
    estoque INTEGER NOT NULL DEFAULT 0 CHECK (estoque >= 0),
    id_categoria BIGINT NOT NULL,

    CONSTRAINT fk_produto_categoria
        FOREIGN KEY (id_categoria)
        REFERENCES categoria(id_categoria)
);
```

## Exercício 1 — Inserção simples

Cadastre individualmente as seguintes categorias utilizando `INSERT INTO`:

| Categoria |
|---|
| Informática |

| Eletrônicos |

Após as inserções, execute:

```sql
SELECT * FROM categoria;
```

## Exercício 3 — Inserção múltipla

Cadastre **quatro novos produtos utilizando apenas um comando `INSERT`**.

Utilize a estrutura:

```sql
INSERT INTO produto
    (nome, preco, estoque, id_categoria)
VALUES
    (...),
    (...),
    (...),
    (...);
```

Os produtos e valores ficam a sua escolha, mas todos devem respeitar as restrições da tabela.

Ao final, utilize:

```sql
SELECT * FROM produto;
```

para verificar o resultado.

## Exercício 4 — Utilizando `DEFAULT` e `RETURNING`

Cadastre um produto **sem informar o estoque**.

Exemplo de estrutura:

```sql
INSERT INTO produto
    (nome, preco, id_categoria)
VALUES
    (...)
RETURNING *;
```

Observe o registro retornado pelo PostgreSQL.

Responda:

1. Qual valor foi atribuído a `estoque`?
2. Por que esse valor foi utilizado?
3. Quem gerou `id_produto`?
4. Qual é a função do `RETURNING *`?

## Exercício 5 — Tentando violar as regras do banco

Execute separadamente tentativas de inserção que representem as situações abaixo:

```text
A. Produto sem nome
B. Produto com preço negativo
C. Produto com estoque negativo
D. Produto relacionado a uma categoria inexistente
E. Categoria com o mesmo nome de uma categoria já cadastrada
```

Para cada tentativa, registre:

| Tentativa | Inserção aceita? | Restrição envolvida | Explique o motivo |
|---|---|---|---|
| Produto sem nome | | | |
| Preço negativo | | | |
| Estoque negativo | | | |
| Categoria inexistente | | | |
| Categoria duplicada | | | |

O objetivo não é apenas corrigir os comandos. **Leia a mensagem apresentada pelo Supabase/PostgreSQL e identifique qual regra do modelo físico impediu a inserção.**

Essa sequência exercita `INSERT` simples, inserção com FK, inserção múltipla, `IDENTITY`, `DEFAULT`, `RETURNING` e, por fim, conecta a inserção às restrições de integridade já estudadas.

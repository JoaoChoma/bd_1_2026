# SQL para Supabase — Referência de Comandos PostgreSQL

> O banco de dados do Supabase é PostgreSQL. Esta referência reúne os principais comandos necessários para trabalhar pelo Supabase SQL Editor.

---

# 1. CREATE TABLE

```sql
CREATE TABLE cliente (
    id_cliente BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    nome VARCHAR(100) NOT NULL,
    email VARCHAR(150) UNIQUE
);
```

Estrutura geral:

```sql
CREATE TABLE nome_tabela (
    coluna tipo restricoes,
    coluna tipo restricoes
);
```

# 3. Identificador automático — IDENTITY

Forma recomendada:

```sql
id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
```

Exemplo:

```sql
CREATE TABLE produto (
    id_produto BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    nome VARCHAR(100) NOT NULL
);
```

Também existe:

```sql
id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY
```

# 4. PRIMARY KEY

Na coluna:

```sql
id_cliente BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
```

Como restrição nomeada:

```sql
CONSTRAINT pk_cliente
    PRIMARY KEY (id_cliente)
```


# 9. FOREIGN KEY

```sql
CREATE TABLE pedido (
    id_pedido BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    data DATE NOT NULL,
    valor NUMERIC(10,2) CHECK (valor >= 0),
    id_cliente BIGINT NOT NULL,

    CONSTRAINT fk_pedido_cliente
        FOREIGN KEY (id_cliente)
        REFERENCES cliente(id_cliente)
);
```

# 10. Ações referenciais

```sql

ON DELETE CASCADE
ON DELETE SET NULL
ON DELETE SET DEFAULT
ON UPDATE CASCADE
```

Exemplo:

```sql

    FOREIGN KEY (id_cliente)
    REFERENCES cliente(id_cliente)
    ON DELETE RESTRICT
```

Adicionar:

```sql

```

Adicionar:


# 19. Remover restrição

```sql

```

---

# 20. DROP TABLE

```sql
DROP TABLE produto;
```

```sql
DROP TABLE IF EXISTS produto;
```

Com dependências:

```sql
DROP TABLE produto CASCADE;
```

> `CASCADE` deve ser utilizado com cuidado, pois pode remover objetos dependentes.

# 23. RETURNING

Retornar o registro inserido:

```sql
INSERT INTO cliente (nome, email)
VALUES ('Ana', 'ana@email.com')
RETURNING *;
```

Retornar somente o identificador:

```sql
INSERT INTO cliente (nome, email)
VALUES ('Ana', 'ana@email.com')
RETURNING id_cliente;
```

# 28. LIKE e ILIKE

```sql

FROM cliente
```


```text

_ → exatamente um caractere
```

# 35. UPDATE

```sql
UPDATE produto
SET preco = 150.00
WHERE id_produto = 10;
```

Mais de uma coluna:

```sql
UPDATE produto
SET preco = 150.00,
    estoque = 20
WHERE id_produto = 10;
```

Com retorno:

```sql
UPDATE produto
SET preco = 150.00
WHERE id_produto = 10
RETURNING *;
```

> `UPDATE` sem `WHERE` altera todas as linhas.

```sql
DELETE FROM produto
```


# 47. ON CONFLICT — UPSERT

Ignorar conflito:

```sql
INSERT INTO cliente (email, nome)
VALUES ('ana@email.com', 'Ana')
ON CONFLICT (email)
DO NOTHING;
```

Atualizar:

```sql
INSERT INTO cliente (email, nome)
VALUES ('ana@email.com', 'Ana')
ON CONFLICT (email)
DO UPDATE
SET nome = EXCLUDED.nome;
```

# 56. TRIGGER

Estrutura:

```sql
CREATE TRIGGER nome_trigger
BEFORE UPDATE ON produto
FOR EACH ROW
EXECUTE FUNCTION nome_funcao();
```

Triggers normalmente são estudadas após funções e DML.

# 57. Row Level Security — RLS

Ativar:

```sql
ALTER TABLE cliente
ENABLE ROW LEVEL SECURITY;
```

Desativar:

```sql
ALTER TABLE cliente
DISABLE ROW LEVEL SECURITY;
```

RLS controla quais linhas podem ser acessadas ou modificadas pelos usuários.

---

# 58. CREATE POLICY

Estrutura:

```sql
CREATE POLICY nome_politica
ON nome_tabela
FOR SELECT
USING (condicao);
```

Exemplo no Supabase:

```sql
CREATE POLICY "usuarios_leem_proprios_dados"
ON perfil
FOR SELECT
USING (auth.uid() = id_usuario);
```

Políticas podem ser criadas para:

```sql
FOR SELECT
FOR INSERT
FOR UPDATE
FOR DELETE
FOR ALL
```

Dependendo da operação, utilizam-se expressões `USING` e/ou `WITH CHECK`.

Remover:

```sql
DROP POLICY nome_politica
ON nome_tabela;
```

# 60. Exemplo completo para Supabase

```sql
CREATE TABLE cliente (
    id_cliente BIGINT GENERATED BY DEFAULT AS IDENTITY,

    nome VARCHAR(100) NOT NULL,
    email VARCHAR(150) NOT NULL,
    ativo BOOLEAN NOT NULL DEFAULT TRUE,
    criado_em TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    CONSTRAINT pk_cliente
        PRIMARY KEY (id_cliente),

    CONSTRAINT uk_cliente_email
        UNIQUE (email)
);

CREATE TABLE pedido (
    id_pedido BIGINT GENERATED BY DEFAULT AS IDENTITY,

    data TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    valor NUMERIC(10,2) NOT NULL,
    id_cliente BIGINT NOT NULL,

    CONSTRAINT pk_pedido
        PRIMARY KEY (id_pedido),

    CONSTRAINT ck_pedido_valor
        CHECK (valor >= 0),

    CONSTRAINT fk_pedido_cliente
        FOREIGN KEY (id_cliente)
        REFERENCES cliente(id_cliente)
        ON DELETE RESTRICT
);

INSERT INTO cliente (nome, email)
VALUES ('Ana', 'ana@email.com')
RETURNING *;

INSERT INTO pedido (valor, id_cliente)
VALUES (250.00, 1)
RETURNING *;

SELECT
    p.id_pedido,
    p.data,
    c.nome AS cliente,
    p.valor
FROM pedido AS p
INNER JOIN cliente AS c
    ON p.id_cliente = c.id_cliente
ORDER BY p.data DESC;
```
